## 1. WiFi Fail + Reconnect Logic dengan AP Activation

### Masalah
Sebelumnya `scheduleReboot()` hanya memanggil `beginStaConnect()` secara infinite loop tanpa pernah aktifkan AP. User tidak bisa reconfigure jika semua WiFi saved gagal.

### Implementasi
Ditambahkan counter `wifiFailCycles` yang increment setiap kali semua saved SSID sudah dicoba dan gagal semua ("full cycle"). Setelah `kMaxFailCycles = 3` full cycles:
- `restoreAp()` dipanggil otomatis — AP `192.168.4.1` aktif
- OLED tampil: `"WiFi Gagal" / "AP Aktif" / "192.168.4.1"` selama 5 detik
- STA tetap retry di background
- Counter reset ke 0 setelah AP aktif (tidak re-trigger tiap 3 cycle)
- Counter reset ke 0 saat `ARDUINO_EVENT_WIFI_STA_GOT_IP`

`handleStaTimeout()` mendapat guard `if (configMode) return` di baris pertama — STA tidak pernah auto-reconnect saat config mode aktif.

## 6. FastConnect — Cache BSSID+Channel

Menyimpan BSSID + channel AP terakhir yang berhasil di NVS namespace `wfast`. Saat reconnect, jika SSID cocok dengan cache, langsung `WiFi.begin(ssid, pass, channel, bssid)` tanpa scan dahulu.

| Kondisi | Aksi |
|---|---|
| Cache valid + SSID cocok | `WiFi.begin()` dengan BSSID+channel, OLED: `"WiFi FastConnect"` |
| Cache tidak ada / SSID beda | `WiFi.begin()` normal |
| Connect timeout dengan cache | `fcClear()` — cache dihapus, AP mungkin ganti channel |
| `GOT_IP` event | `fcSave()` update cache |

Cache di-load saat boot via `fcLoad()` setelah `loadWifiList()`.

### Root Cause
`setInterval(load, 5000)` overwrite semua field form setiap 5 detik, termasuk saat user sedang mengetik.

### Fix

- `load(true)`: load penuh — dipanggil saat pertama buka halaman dan setelah simpan berhasil
- Setelah save berhasil: `dirty = false`, lalu `load(true)` setelah 1.5 detik

## 10. MQTT Health Monitoring

`publishHealth()` dipanggil dari `loop()` setiap 30 detik (`kHealthIntervalMs = 30000`). Publish ke topic `sems/health`:

```json
{"up":60,"heap":203296,"rssi":-30,"ip":"192.168.x.x","if":"wifi","time":"11:51"}
```

Field:
- `up` — uptime dalam detik
- `heap` — free heap bytes
- `rssi` — WiFi RSSI dBm (0 jika ETH)
- `ip` — IP aktif (ETH prioritas, lalu STA)
- `if` — `"eth"` / `"wifi"` / `"none"`
- `time` — jam WIB dari NTP `"HH:MM"`

`mqttHealthLastMs = 0` saat pertama connect → publish langsung tanpa tunggu 30s.

Juga publish `sems/status` saat connect: `{"online":true,"fw":"0.1.0"}`.

Confirmed working via `mosquitto_sub` — data masuk setiap 30s.

## 13. Fix OLED Kacau — Overlay Tumpang Tindih

### Root Cause

`oledHeartbeat()` lama memanggil `oled.sendBuffer()` sendiri setelah menggambar overlay di atas buffer yang tidak fresh. Saat `oledShow` aktif, `updateOled` return early setelah heartbeat, sehingga buffer `oledShow` tertimpa partial overlay. Tampilan jadi kacau.

### Fix

Refactor menjadi dua fungsi terpisah:

- `oledDrawOverlay(now)` — hanya gambar ke buffer, tidak `sendBuffer()`
- `updateOled(now)` — satu titik `sendBuffer()` per tick

Alur baru:
1. Hitung `hbTick` (setiap 500ms)
2. Jika `oledShow` aktif: overlay + sendBuffer, return
3. Jika page interval tercapai: `clearBuffer` → `drawPage*` → `oledDrawOverlay` → `sendBuffer`
4. Jika hanya hbTick: sama seperti 3 (refresh halaman + overlay)
5. `oledDrawPage()` juga memanggil `oledDrawOverlay` agar button press langsung tampil overlay

## 14. MQTT LWT — Device Offline Detection

LWT (Last Will Testament) ditambahkan di `connect()` call. Saat device disconnect (power off / network drop / timeout keepalive), broker otomatis publish ke `sems/{MAC}/status`:

```json
{"online": false}
```

Parameter LWT: `retain=true`, `qos=0`. Saat device connect normal, tetap publish `{"online":true,"fw":"0.1.0"}` secara eksplisit.

Node-RED `format status` function node handle kedua kondisi:
- `online: true` → `"[AABBCCDD1122] 🟢 Online — FW 0.1.0"`
- `online: false` (LWT) → `"[AABBCCDD1122] 🔴 Offline"`

## Sesi Lanjutan — Modbus RS485 Implementation (PM2xxx/EM6400)

### Ringkasan

Implementasi penuh pembacaan Modbus RTU dari meter Schneider PM2xxx/EM6400 series, dengan config register map yang bisa diubah via web UI, support 1-phase dan 3-phase, serta publish data meter ke MQTT.

### 16. ModbusConfig — Register Map Configurable via NVS

`ModbusConfig` struct menggantikan konstanta hardcoded lama (`kModbusSlaveId`, `kRegVoltage`, dst). Field: `slaveId`, `baud`, `pollMs`, `phase` (1 atau 3), plus register address untuk tiap parameter — terpisah untuk mode 1-phase (`r1*`) dan 3-phase (`r3*`). Default value mengikuti register map PM2230 (FC03, FP32 big-endian, 0-based).

`loadModbusConfig()` / `saveModbusConfig()` baca/tulis semua field ke NVS namespace `modbus`.

### 17. MeterData1Ph / MeterData3Ph

`MeterData` lama (flat: voltage/current/power/energy/freq) dipecah jadi dua struct:
- `MeterData1Ph`: v, a, kw, kvar, kva, pf, kwh, hz
- `MeterData3Ph`: va/vb/vc, vll/vln, ia/ib/ic/iavg, pa/pb/pc/ptot, qa/qb/qc/qtot, sa/sb/sc/stot, pfa/pfb/pfc/pftot, kwh, hz

Hanya salah satu yang `valid` sesuai `modbusCfg.phase` aktif — struct lainnya di-invalidate.

### 18. Decode 4Q Floating Point Power Factor

Register PF Schneider pakai format "4Q_FP_PF" (bukan signed float biasa). `decode4QFpPf()`:
```cpp
if (reg > 1.0f)       return  2.0f - reg;  // leading
else if (reg < -1.0f) return -2.0f - reg;  // leading
return reg;                                  // lagging / unity
```
PF Total (`r3Pftot`, register 3191) pakai FLOAT32 biasa — dibaca langsung tanpa decode 4Q.

### 19. handleModbus() — Poll per Fasa

Macro `MB_READ(field, reg)` dan `MB_READ4Q(field, reg)` menyederhanakan pembacaan berantai — tiap gagal set `ok=false` dan skip sisa baca. Polling pakai local `MeterData1Ph m` / `MeterData3Ph m`, hanya commit ke `meter1`/`meter3` global kalau semua baca sukses (`ok == true`).

### 20. Publish MQTT Meter Data — Split Topic 3-Phase

`publishMeter()`:
- Mode 1-phase → topic `meter`, satu payload JSON (v, a, kw, kvar, kva, pf, kwh, hz)
- Mode 3-phase → payload dipecah dua topic karena melebihi batas 256 byte:
  - `meter/vi` — voltage + current + active power per fasa
  - `meter/vi2` (power factor lanjutan) — reactive/apparent power, PF, kwh, hz

### 21. Web UI `/modbus` — Config Register Map

Halaman baru `handleModbusPage()` dengan:
- Card status meter (live, polling `/api/modbus` tiap 3 detik)
- Card preset: tombol "PM2230/PM2120/EM6400 — 1-Phase" dan "— 3-Phase" auto-isi semua register field
- Card koneksi RS485: slave ID, baud rate (dropdown 1200–115200), poll interval, radio pilih mode fasa
- Card register map terpisah untuk 1-phase dan 3-phase (toggle show/hide sesuai radio)
- JS flag `dirty` (pola sama seperti MQTT form) — cegah field ke-overwrite polling saat user ngetik
- `handleModbusApi()` (GET, live status + config) dan `handleModbusSave()` (POST, validasi + `saveModbusConfig()`)

Endpoint terdaftar: `/modbus`, `/api/modbus`, `/api/modbus/save`.

Baud rate baru butuh reboot untuk aktif (banner kuning info di config mode).

### 22. Setup() — Load Config Sebelum Serial2.begin()

### 24. Partisi Flash — NVS vs SPIFFS, dan Rekomendasi Perluasan

**Kenapa `no_fs.csv` dipilih (bukan `default.csv` bawaan):**

| Partisi | app0/app1 (masing-masing) | Data storage | Cocok untuk |
|---|---|---|---|
| `default.csv` (lama) | 0x140000 = 1.310.720 byte (~1,25 MB) | SPIFFS 0x160000 (~1,4 MB) | Kalau butuh file storage (upload web, log besar) |
| `no_fs.csv` (dipakai sekarang) | 0x1F0000 = 1.966.080 byte (~1,92 MB) | Tidak ada (SPIFFS dihapus) | Project ini — cuma butuh NVS untuk config & ring buffer kecil, tidak ada file storage |

2. **Board prod (ESP32-WROOM-32UE-N16, 16MB)** — jangan pakai partisi 4MB punya. 3. Kalau nanti butuh simpan file besar (misal grafik historis, log CSV panjang), baru pertimbangkan LittleFS partisi kecil khusus — jangan pakai SPIFFS (LittleFS lebih tahan wear, lebih cepat).

## Sesi Lanjutan 2 — Energy Ring Buffer NVS (Backup Data, Bukan Akumulasi)

### Tujuan

Backup data kWh secara periodik ke NVS, supaya kalau MQTT/broker loss data, nilai energy tetap aman tersimpan di device — bukan untuk akumulasi/kalkulasi.

### Kenapa NVS (bukan SPIFFS/LittleFS)

- Sudah ada di partisi, tidak butuh format atau partisi baru
- Survive reboot + power-off
- 14 entry × ~12 bytes = ~170 bytes — jauh di bawah limit NVS
- Write endurance: 2 write/hari × 365 = ~730 write/tahun → aman bertahun-tahun (limit ~10.000 cycles/sector)

SPIFFS/LittleFS overkill untuk data sekecil ini, dan partisi `no_fs` (lihat item 23 di atas) memang tidak menyediakan SPIFFS.

### Struktur Ring Buffer

```cpp
namespace "energylog"  // NVS namespace baru

struct EnergyEntry {
  uint32_t ts;   // Unix timestamp (UTC+7 WIB)
  float    kwh;  // Nilai kWh absolut dari meter saat snapshot
};

// Key NVS:
// "idx"      → uint8_t, index slot berikutnya (0–13, wraps)
// "e00"–"e13" → bytes EnergyEntry (8 bytes per entry)
```

Ring buffer 14 slot bergilir — slot terlama otomatis tertimpa saat index wrap.
