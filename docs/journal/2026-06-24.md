## Sesi Ini — OLED UI Polish, Hardware I2C Pin Swapping, dan W5500 SPI Debugging

### Fitur & Masalah yang Berhasil Diselesaikan

#### 1. Masalah Upload & COM Port (`platformio.ini`)
- **Kondisi:** Sistem mendeteksi kegagalan koneksi saat mencoba mem-flash ke port default `COM5`.
- **Root cause:** Perangkat terhubung ke USB-to-UART Bridge pada port `COM6`.
- **Fix:** Memperbarui parameter `upload_port` dan `monitor_port` menjadi `COM6` di [platformio.ini](file:///D:/enerma/bms/2026/pm1611-rs485-reader/firmware/platformio.ini). Kecepatan `upload_speed` diturunkan sementara ke `460800` untuk meningkatkan stabilitas proses flashing.

#### 2. Debugging I2C OLED (SSD1306/SH1106 Driver Mismatch)
- **Kondisi:** Awalnya terjadi error berulang pada serial monitor:
  `i2cWrite(): i2c_master_transmit failed: [259] ESP_ERR_INVALID_STATE`
- **Root cause 1 (Pin Swap):** Jalur hardware pada header OLED dihubungkan terbalik dengan pin default ESP32 (Header Pin 3 = GPIO21 terhubung ke SCL, Header Pin 4 = GPIO22 terhubung ke SDA).
- **Fix 1:** Menukar konfigurasi I2C di software menggunakan `Wire.begin(22, 21)` (SDA=22, SCL=21).
- **Root cause 2 (Driver & Shift):** Ketika dicoba menggunakan driver SH1106, layar menyala tetapi terjadi pergeseran kolom (2-pixel shift ke kiri) yang memotong tulisan di sisi kiri dan menampilkan garis noise abstrak di sisi kanan.
- **Fix 2:** Mengembalikan driver ke SSD1306 (`U8G2_SSD1306_128X64_NONAME_F_HW_I2C`) karena modul OLED fisik sebenarnya berbasis chip SSD1306. Masalah pixel shift dan noise di tepi layar terselesaikan sepenuhnya.

#### 3. Penyesuaian Rotasi & Batas Warna Kuning-Biru
- **Kondisi:** Teks "Heap Usage" memiliki 2 baris atas berwarna kuning dan 1 baris kosong (blank space) di tengah tulisan.
- **Root cause:** Penggunaan rotasi 180 derajat (`U8G2_R2`) membalikkan koordinat rendering (`y = 0` berada di zona fisik biru bawah, dan `y = 48` berada di zona fisik kuning atas). Ini menyebabkan teks `Heap Usage` di `y = 49` menabrak batas transisi warna fisik dan gap hitam OLED.
- **Fix:** Mengubah rotasi OLED menjadi **`U8G2_R0`** di constructor agar koordinat software sejajar natural dengan letak fisik (kuning di atas untuk Header `y = 0..14`, biru di bawah untuk data `y = 15..63`).

#### 4. Pembaruan Desain Grafis (UI Polish)
- Mengganti ikon font standard U8g2 dengan custom geometric pixel art:
  - **System Page:** Menampilkan ikon Microchip detail dan bar grafis dinamis (Heap Usage) yang menyesuaikan sisa RAM secara proporsional.
  - **WiFi Page:** Menampilkan ikon bar sinyal WiFi dinamis berdasarkan kekuatan `RSSI` (dBm) serta animasi loading bar saat connecting.
  - **LAN Page:** Menampilkan ikon port RJ45/Ethernet beserta visualisasi status kabel LAN.
- Memindahkan heartbeat dot (kedipan indikator hidup) ke pojok kanan atas zona kuning agar selalu terlihat di semua halaman menu.

#### 5. Debugging SPI W5500 Ethernet (DHCP Connection)
- **Kondisi:** Kabel LAN dicolokkan dan switch berkedip, tetapi modul tidak mendapat IP Address (Link UP, status No IP).
- **Root cause 1 (SPI Host):** Inisialisasi awal menggunakan `SPI2_HOST` (HSPI), padahal modul W5500 secara fisik terhubung pada jalur default VSPI (GPIO18=SCLK, GPIO19=MISO, GPIO23=MOSI, GPIO5=CS).
- **Fix 1:** Mengubah host menjadi `SPI3_HOST` (VSPI).
- **Root cause 2 (v3.x API Migration):** Pada `arduino-esp32` v3.x, parameter host integer tidak lagi diizinkan secara langsung. Inisialisasi harus melewatkan instance `SPIClass` setelah bus dimulai.
- **Fix 2:** Menambahkan `#include <SPI.h>`, memulai bus `SPI.begin(18, 19, 23, kEthCs)`, dan memanggil `ETH.begin(ETH_PHY_W5500, -1, kEthCs, -1, kEthRst, SPI)`.
- **Root cause 3 (Chip Cache/State):** W5500 perlu dibersihkan dan direset saat startup agar request DHCP tidak diabaikan/ditolak router.
- **Fix 3:** Menambahkan siklus hardware reset manual dengan menarik pin `kEthRst` (GPIO26) ke LOW selama 50ms lalu mengembalikannya ke HIGH 100ms sebelum menginisialisasi modul. Mode IRQ diubah ke Polling (`irq = -1`) dan auto-detect PHY diset ke `-1` untuk stabilitas maksimal.
- **Hasil Akhir:** W5500 berhasil terhubung sepenuhnya ke jaringan lokal, menerima IP **`192.168.1.11`** via DHCP, dan menjadi rute default utama (*Default Route Priority*).
