## 3. Review Teknis Codex

### Yang sudah benar

- **Rename topic dilakukan di satu source of truth.** Fungsi `mqttSwitchTopic()` menjadi pusat pembentukan topic, sehingga subscribe command dan publish state otomatis mengikuti pola baru.
- **Subscribe command per relay ikut berubah konsisten.** Saat MQTT connect, firmware loop `i = 0..3` dan subscribe ke `mqttSwitchTopic(i)`, sehingga akan subscribe ke `control/slave_1` sampai `control/slave_4`.
- **Publish state retained ikut pola baru.** `mqttSwitchStateTopic(i)` dibangun dari `mqttSwitchTopic(i) + "/state"`, sehingga state topic ikut berubah ke `control/slave_N/state`.
- **Komentar sudah diperbarui.** Dokumentasi inline tidak lagi menyebut `switch_N` sebagai topic aktif, sehingga pembaca kode tidak diarahkan ke pola lama.
- **Device name reconnect behavior tetap relevan.** Komentar di `handleDeviceConfigSaveApi()` sudah mencantumkan `control/slave_N`, dan logic reconnect tetap penting karena `device_name` mengubah base topic.

### Concern / risiko migrasi

1. **Breaking change untuk integrasi eksternal.** Node-RED, broker automation, dashboard, atau service lain yang masih publish ke `control/switch_N` tidak akan lagi mengontrol relay setelah firmware ini dipakai.
2. **Tidak ada dual-subscribe masa transisi.** Firmware hanya subscribe ke topic baru. Jika deployment butuh backward compatibility, bisa dipertimbangkan subscribe sementara ke dua pola: `control/slave_N` dan `control/switch_N`.
3. **State topic juga ikut berubah.** Konsumen yang memantau `control/switch_N/state` harus pindah ke `control/slave_N/state`.
4. **Perlu update dokumentasi operasional.** README, manual, Node-RED flow, dan contoh MQTT command harus disinkronkan agar tidak ada operator yang memakai topic lama.

### Catatan Error Build

Saat menjalankan `pio run` tanpa env eksplisit, PlatformIO memakai default env `network_test`. Build env tersebut gagal di `firmware/src/main_net.cpp`, bukan di `main.cpp` firmware utama.

```text

src/main_net.cpp:85:3: error: 'esp_read_mac' was not declared in this scope
```

Analisis sementara:

- Ini issue pada env `network_test` / `main_net.cpp` lama.
- Error tidak terkait perubahan OLED.
- Firmware utama tetap valid karena `pio run -e esp32dev` sukses.

Rekomendasi:

- Untuk verifikasi firmware utama, gunakan `pio run -e esp32dev`.
- Jika env `network_test` masih diperlukan, perbaiki kompatibilitas API MAC di `main_net.cpp` untuk arduino-esp32 versi yang sedang dipakai, atau keluarkan env tersebut dari default jika sudah tidak menjadi jalur build utama.
