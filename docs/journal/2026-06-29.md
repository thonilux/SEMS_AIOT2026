## 1. Rewrite main.cpp — arduino-esp32 v3.x Architecture

### Motivasi

Requirement B4T: WebServer harus accessible dari WiFi AP, WiFi STA, **dan** LAN (W5500) secara simultan. Dengan `Ethernet_Generic` (v2.x), W5500 punya network stack terpisah dari lwIP WiFi — WebServer hanya bisa serve dari WiFi. Solusi: upgrade ke arduino-esp32 v3.x di mana semua interface (WiFi + W5500 via ETH.h) masuk satu lwIP stack.

### Perubahan Arsitektur

| Aspek | Sebelum (v2.x) | Sesudah (v3.x) |
|---|---|---|
| W5500 driver | `Ethernet_Generic.h` | `ETH.h` native (lwIP) |
| MQTT transport | `WiFiClient` | `NetworkClient` (auto-route lwIP) |
| Network events | polling `WiFi.status()` di `loop()` | `WiFi.onEvent()` event-driven |
| Routing priority | manual flag `ethReady` | `ETH.setDefault()` / `WiFi.STA.setDefault()` |
| WebServer scope | WiFi saja | semua interface (satu lwIP stack) |
| HTML generation | chained `+=` | `html.reserve(N)` + `+=` |
| HTTP routing | `server.on(path, handler)` | `server.on(path, HTTP_GET/POST, handler)` |

### Platform

```ini
platform = https://github.com/pioarduino/platform-espressif32/releases/download/55.03.39/platform-espressif32.zip
```

pioarduino 55.03.39 = arduino-esp32 3.3.9 + ESP-IDF 5.5.x

### Bug yang Ditemukan Saat Build

**`WiFi.setDefault()` tidak ada** — `WiFiClass` tidak extend `NetworkInterface`. Yang benar:
- `ETH.setDefault()` ✓ — `ETHClass` extend `NetworkInterface`  
- `WiFi.STA.setDefault()` ✓ — `STAClass` extend `NetworkInterface`, exposed sebagai `WiFiClass::STA`

**Toolchain incompatibility di Git Bash** — pioarduino 55.x pakai toolchain baru `xtensa-esp-elf` yang install via `idf_tools.py`. Tidak kompatibel dengan Git Bash/MinGW di Windows. **Fix: selalu jalankan `pio run` dari PowerShell, bukan Git Bash.**

## 2. OLED Freeze Fix

### Root Cause

`oledHeartbeat()` dipanggil **setelah** guard `if (now < oledUntilMs) return` di `updateOled()`. Saat overlay aktif (e.g. boot message, "WiFi Connecting"), heartbeat ikut diblok → OLED freeze di overlay selamanya jika event handler terus extend `oledUntilMs`.

### Fix

```cpp
static void updateOled(uint32_t now) {
  if (!oledReady) return;
  oledHeartbeat(now);          // heartbeat selalu jalan
  if (now < oledUntilMs) return; // overlay: skip page rotate saja
  if (now - oledPageMs < kPageIntervalMs) return;
  oledPageMs = now;
  oledPage = (oledPage + 1) % 3;
  oledDrawPage(oledPage);
}
```

## 3. Upload Troubleshooting — Kronologi

Upload firmware setelah rewrite membutuhkan banyak langkah debug:

| Error | Root Cause | Fix |
|---|---|---|
| `firmware.bin: used by another process` | VS Code PlatformIO extension hold file lock | Kill semua terminal VS Code, upload dari terminal baru |
| `No serial data received` | Port berubah COM5 → COM6 setelah reconnect | Update `upload_port = COM6` di platformio.ini |
| `UnicodeEncodeError cp1252` | esptool output pakai karakter Unicode, PowerShell default cp1252 | Set `$env:PYTHONIOENCODING="utf-8"` sebelum `pio run` |
| `COM5 PermissionError` | Serial monitor VS Code masih terbuka | Tutup serial monitor sebelum upload |

**Upload akhirnya sukses** dari PowerShell dengan `$env:PYTHONIOENCODING="utf-8"`.

## 4. Hardware Fixes (commit 3d46fdd, oleh Hisbull)

Setelah rewrite berjalan, dilakukan penyesuaian hardware:

- **I2C pin swap:** `Wire.begin(22, 21)` (SDA=22, SCL=21) — hardware terhubung terbalik
- **OLED rotasi:** `U8G2_R0` (bukan `U8G2_R2`) agar koordinat sejajar dengan zona warna kuning/biru fisik
- **W5500 SPI host:** `SPI3_HOST` (VSPI, GPIO18/19/23) bukan `SPI2_HOST`
- **ETH init v3.x:** `SPI.begin(18,19,23,kEthCs)` lalu `ETH.begin(ETH_PHY_W5500, -1, kEthCs, -1, kEthRst, SPI)`
- **Hardware reset W5500:** RST pin LOW 50ms → HIGH 100ms sebelum `ETH.begin()`

Hasilnya: W5500 DHCP sukses, IP `192.168.1.11`, WebServer accessible dari WiFi AP, WiFi STA, dan LAN bersamaan.
