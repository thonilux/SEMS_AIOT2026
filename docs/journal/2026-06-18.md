### Step 3f — Fallback ke Saved WiFi Lain (`63ce0db`)

Saat STA timeout, bukan langsung menyerah — coba network lain dari saved list:

```
Boot → scan → pilih RSSI terbaik (1/3) → timeout?
  → scan → pilih untried terbaik (2/3) → timeout?
    → scan → coba sisa (3/3) → timeout?
      → scheduleReboot()
```

Implementasi: `triedMask` bitmask (uint8_t, support 8 network), `pickBestWifi(skipMask)` skip yang sudah dicoba.

OLED tampilkan `(1/3)`, `(2/3)` saat connecting.

**Fix:** `delay(500)` sebelum scan setelah AP restore — radio perlu settle setelah mode switch.

## Sesi Sore — WiFi Reconnect Fixes

### Fix 1: Retry WiFi setiap 10s selama countdown (`16c4b6c`)

Saat countdown 60s aktif, `handleRebootCountdown` sekarang silent scan tiap 10 detik.
Kalau ada saved network yang muncul → cancel reboot, `beginStaConnect()` langsung.

### Fix 2: Retry scan 3x sebelum scheduleReboot (`d237893`)

**Bug:** Saat STA drop, `beginStaConnect()` → `pickBestWifi()` → scan kosong → langsung `scheduleReboot()`.
Router bisa momentary unstable, scan satu kali tidak cukup.

**Fix:** `scanRetryCount` — kalau scan kosong dan belum ada network yang dicoba:
- Retry scan hingga `kMaxScanRetry` (3x), interval 15 detik per retry
- Baru `scheduleReboot()` setelah 3x scan berturut-turut kosong
- Kalau network muncul di retry → connect normal tanpa reboot

```
STA drop → scan → kosong (retry 1/3, tunggu 15s)
         → scan → kosong (retry 2/3, tunggu 15s)
         → scan → kosong (retry 3/3) → scheduleReboot (countdown 60s)
                → nemu network → connect normal
```

`scanRetryCount` di-reset ke 0 saat `beginStaConnect()` fresh round dan saat connect sukses.

## Catatan Teknis Penting

### Mengapa `escapeJs` dihapus permanen
C++ multi-level string escaping untuk regex JavaScript sangat fragile. Pattern `\\'` di dalam `F("...")` menghasilkan output yang berbeda tergantung compiler. Solusi: **jangan pernah generate JS string dengan escaping di C++**. Gunakan `data-*` attribute HTML + `addEventListener` — browser handle escaping sendiri.

### Mengapa scan async
`WiFi.scanNetworks(false)` (blocking) di `WIFI_AP_STA` mode saat STA reconnecting bisa hang 10-20 detik atau return -2. Solusi: `WiFi.scanNetworks(true)` (async) + poll `WiFi.scanComplete()` dari handler terpisah.

### Mengapa RTC_DATA_ATTR untuk WiFi fail flag
`Preferences` (NVS) terlalu berat untuk flag sementara — write cycle terbatas. `RTC_DATA_ATTR` survive software reboot tapi reset saat power-off, persis behavior yang diinginkan.
